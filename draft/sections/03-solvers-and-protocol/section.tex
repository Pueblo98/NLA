\section{Numerical methods and comparison protocol}
\label{sec:solvers-protocol}

Section 2 gave a sparse, symmetric positive-definite system $Ax=b$ for
the free displacements. We now compare ways to solve it. Direct methods
factor the matrix; iterative methods improve a displacement estimate.
Each iteration approaches the same static equilibrium, not a later time.

\subsection{Solution methods}
For an iterate $x_k$, the residual $r_k=b-Ax_k$ measures the remaining
force imbalance. We write $P=\operatorname{diag}(A)$ for the diagonal
stiffness entries. The following methods offer different ways to reduce
that imbalance~\cite{saad-iterative}.

\subsubsection*{Cholesky}
Cholesky uses positive definiteness to write $A=LL^T$, with $L$ lower
triangular. Solving $Ly=b$ and then $L^Tx=y$ gives the displacement.
We use it in the small example because it directly exploits our matrix's
structure; $y$ is only an intermediate vector.

\subsubsection*{LU and the direct reference}
Pivoted LU factors a row-permuted matrix into lower and upper triangular
factors, then solves the resulting triangular systems. Sparse LU provides
$x_{\mathrm{ref}}$, a comparison solution on the same mesh. It is
\emph{untimed}, not a competitor in the iterative timing table. The small
example also forms $A^{-1}b$ for illustration, not as the recommended method.

\subsubsection*{Jacobi}
Jacobi corrects every component using only the previous iterate:
$x_{k+1}=x_k+P^{-1}r_k$. We try it as a simple baseline with inexpensive
updates. Positive definiteness alone does not guarantee its convergence.

\subsubsection*{Damped Jacobi}
Damped Jacobi takes a smaller correction,
$x_{k+1}=x_k+\omega P^{-1}r_k$. We use $\omega=0.5$ to test whether
reducing the step improves convergence. This weight is not guaranteed
to work for every positive-definite matrix.

\subsubsection*{Gauss--Seidel}
Gauss--Seidel updates components sequentially, immediately reusing the
newest values. Comparing it with Jacobi tests the benefit of using fresh
information. It converges for our positive-definite system in exact
arithmetic, though it may still require many sweeps.

\subsubsection*{Steepest descent}
Steepest descent moves along the residual, choosing the step that minimizes
$\tfrac12 x^TAx-b^Tx$ in that direction:
$x_{k+1}=x_k+\alpha_k r_k$, where
$\alpha_k=(r_k^Tr_k)/(r_k^TAr_k)$. We include it to test whether choosing
the step from the matrix improves on fixed-step corrections.

\subsubsection*{Conjugate gradients (CG)}
CG combines the residual with previous search information rather than
starting afresh at every step. It minimizes the same quadratic energy
over an expanding search space. We expect it to suit this problem because
it exploits both symmetry and positive definiteness~\cite{saad-iterative}.

\subsubsection*{Diagonal preconditioned CG (PCG)}
PCG scales the residual by $P^{-1}$ before constructing its search
direction. We test whether accounting for different diagonal stiffnesses
reduces the work needed by CG. The scaling preserves the solution, but
its benefit must outweigh its cost. SciPy receives the inverse action
$P^{-1}$ as its \texttt{M} argument~\cite{scipy-cg}.

\subsubsection*{GMRES}
GMRES chooses the smallest Euclidean residual in a space built by repeated
multiplication by $A$. We include this more general method as a comparison
with CG. Our unpreconditioned run uses a restart length equal to the number
of free unknowns: full GMRES, whose stored basis and orthogonalization can
become expensive on larger meshes~\cite{scipy-gmres}.

\subsubsection*{MINRES}
MINRES also minimizes the residual, but uses symmetry to update the
solution through a short recurrence. It provides a symmetry-aware
comparison with GMRES and CG. We do not need it because of indefiniteness:
our supported matrix is positive definite~\cite{saad-iterative}.

\subsection{Common stopping and timing rules}
All eight iterative methods use identical $A,b$, start from $x_0=0$ and
have a 20\,000-iteration budget. For nonzero $b$, acceptance requires the
independently recomputed relative residual
\begin{equation}
 \rho(x)=\frac{\lVert b-Ax\rVert_2}{\lVert b\rVert_2}<10^{-8},
 \label{eq:solvers-acceptance}
\end{equation}
where $\lVert\cdot\rVert_2$ is the Euclidean norm. One iteration is a full
stationary sweep or a Krylov step; GMRES counts inner Arnoldi steps, not
restart cycles. Different work per step prevents ranking speed by counts
alone. The solver handles $b=0$ by returning $x=0$ immediately; the current
benchmark's outer relative-error calculations require nonzero denominators.

CG and PCG use relative tolerance $10^{-8}$ and absolute tolerance zero.
MINRES uses native tolerance zero and an explicit true-residual stopping
callback. GMRES uses the legacy callback convention for inner-step counting;
its history contains Arnoldi residual estimates, unlike the explicitly
computed histories of the other methods. Final acceptance always uses
Eq.~\eqref{eq:solvers-acceptance}. We retain native status and acceptance
separately, including breakdowns and budget exhaustion. Stationary and
steepest-descent runs stop if $\rho$ is nonfinite or exceeds $10^{10}$.
Failed-run times are not times to the requested accuracy.

We retain three timed runs and report their minimum, collecting histories
separately. Timings include iterative setup and required stopping checks,
including MINRES's per-step true residual. They exclude assembly,
conditioning diagnostics, the LU reference and final independent checks.
Thus they are \emph{setup-inclusive iterative times}, not separate setup
and solve measurements. Machine and software details accompany the data;
small timing differences do not establish general rankings.

\subsection{Accuracy and validation}
We report time, iterations, residual and the relative reference difference
\begin{equation}
 e_{\mathrm{ref}}(x)=
 \frac{\lVert x-x_{\mathrm{ref}}\rVert_2}{\lVert x_{\mathrm{ref}}\rVert_2}.
 \label{eq:solvers-reference-error}
\end{equation}
\nopagebreak[4]
We check the reference's residual too. Poor conditioning can leave
appreciable displacement error despite a small residual. These are
solver-reliability checks; load perturbations at fixed $A$ instead test
input sensitivity, with magnitude and direction recorded.

Solver agreement does not establish continuum accuracy. Refinement must
preserve the physical case and compare matching locations or observables.
Section 4 also checks prescribed displacements and force/moment balance
using Section 2's support reactions, not free-row residuals. Its separate
exact affine test uses roller supports, not the clamped benchmark.
