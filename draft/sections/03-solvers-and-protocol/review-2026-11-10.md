## Findings to apply to the draft

1. **Distinguish measured methods from reference calculations.** The saved
   large-system table measures eight iterative implementations. Sparse LU
   provides the same-mesh reference; its runtime is not a row in that table.
   Dense pivoted LU, explicit inversion and Cholesky are compared for the
   12-unknown example. Do not describe these as a measured large-system
   direct-versus-iterative timing comparison. Explain Cholesky through
   `A=LL^T` and triangular solves, using the supported SPD matrix established
   in Section 2. An explicit inverse is an illustration for the tiny example.

2. **Keep the actual comparison settings attached to the evidence.** The
   current progress comparison uses `force_driven(20)`: a clamped, traction-
   loaded square with 840 free displacement unknowns. Every method uses the
   same reduced `A,b`, zero initial guess, target
   `||b-Ax||_2/||b||_2 < 1e-8` and cap of 20,000 iterations. For `b=0`, the
   implementation returns the zero solution with zero iterations and zero
   absolute residual. The 3,000-iteration budget and proposed GMRES restart
   of 50 in the historical comparison plan are for a different plan; they
   do not describe these results. Keep the square's detailed physical
   specification in Section 4.

3. **Define diagonal preconditioning accurately.** Write `P=diag(A)` and
   explain that PCG applies `P^{-1}` to residuals. The code passes the inverse
   diagonal operator as SciPy's argument `M`; do not confuse this with the
   matrix `P` being approximated. The diagonal is positive for the supported
   SPD problem. Ordinary Jacobi has no general convergence guarantee from
   SPD alone. The damped Jacobi run uses weight `0.5`, not `2/3`. Explain
   Gauss-Seidel as updating components using the most recent available
   values, and steepest descent as choosing a residual direction and its
   energy-minimizing step. A concise explanation is preferable to another
   matrix-assembly derivation.

4. **State the actual Krylov conventions.** CG is directly motivated by
   symmetry and positive definiteness. GMRES and MINRES can serve as
   comparisons; do not imply they are needed because this matrix is
   nonsymmetric or indefinite. The saved GMRES run is unpreconditioned,
   with `restart=A.shape[0]`; the callback counts inner Arnoldi iterations
   through `callback_type="legacy"`. Its plotted history is an Arnoldi
   residual estimate, with a separately recomputed final residual. MINRES
   uses native `rtol=0` and a callback that explicitly checks the true
   relative residual, stopping through a caught exception at the common
   target. Its saved `callback_target` status is intentional. Native solver
   status and independently recomputed acceptance must both be retained.

5. **Describe historical timings as implemented.** Each time is the minimum
   of three runs with history collection disabled. The timed `iterative`
   call includes method-specific setup, such as diagonal preconditioner
   construction or the Gauss-Seidel splitting, and required stopping checks.
   MINRES still computes a true residual in every timed callback. Assembly,
   conditioning diagnostics and construction of the LU reference are
   outside those timings. The final independent acceptance/error calculation
   is also outside the timed call. Consequently the existing measurements
   are not separately measured setup and solve times. Propose separate
   setup/factorization and solve measurements for future experiments if
   desired, but label that as a change of protocol requiring new results.
   Small timing differences between CG and diagonal PCG should not support
   a general speed ranking from these three repeats.

6. **Preserve failures and distinguish error measures.** Ordinary Jacobi
   reaches the divergence guard; damped Jacobi and steepest descent exhaust
   the cap without acceptance. Their runtimes are unsuccessful-run costs.
   Define the same-mesh reference difference as
   `||x-x_ref||_2/||x_ref||_2`, where `x_ref` is the sparse LU solution.
   This is agreement with a numerical reference, not error against an exact
   continuum displacement. A small residual does not by itself establish
   a small displacement error when conditioning is poor. A mesh comparison
   must preserve physical geometry/loading and compare matching locations
   or consistently defined observables. The three existing mesh levels
   give initial refinement evidence, not a completed discretization-error
   study.

7. **Connect accuracy checks to Section 2.** State that later validation
   reconstructs the full displacement, verifies prescribed values and
   checks applied forces plus support reactions for force and moment
   balance. Reuse Section 2's reaction formula. The separate affine exact-
   solution test uses roller supports rather than the fully clamped case;
   its agreement cannot be described as an exact solution of the clamped
   benchmark. Leave actual numerical outcomes and figures to Sections 4
   and 6.

## Verification performed

A fresh standard-library audit of `drafts/results/solver_comparison.csv`,
`benchmark.json` and `histories.json` passed for all eight methods:

- Methods, iteration counts, residuals, reference differences, statuses,
  acceptance flags and best times agree between CSV and JSON.
- Acceptance matches a finite final relative residual strictly below the
  saved tolerance.
- Each best time equals the minimum of its three saved timing repeats.
- Every history has one initial value plus one value per recorded iteration.

These are saved-data consistency checks and a code inspection. No FEM or
solver experiment was rerun, no timing result was regenerated, and no
unseen prose or PDF is approved by this review.
